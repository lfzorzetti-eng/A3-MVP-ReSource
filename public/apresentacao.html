Visão de Transformação com IA

Uma camada de inteligência não invasiva

A ReSource não substitui o sistema de gestão existente. Ela consome os dados operacionais da empresa, os vetoriza e usa um agente de IA (RAG + LLM) para classificar resíduos, correlacionar estoque e sugerir autonomamente destinações sustentáveis — melhorando a gestão sem tocar no banco original.

1 · Dados operacionais

Cadastros, estoque, movimentações e políticas de uma empresa fictícia, guardados no MongoDB Atlas como se fosse o sistema legado.

2 · Vetorização (RAG)

Textos do banco são convertidos em embeddings e indexados num banco vetorial (papel do Qdrant) para busca semântica.

3 · Agente de IA

O Ollama Cloud (modelo gemma4:31b-cloud) recebe o contexto recuperado e responde: relatórios de estoque, consultas e destinações.

Escopo desta entrega (MVP): RF01 a RF06 operando sobre dados fictícios, publicado na Vercel e com login por perfil de setor. Identificação de resíduos por foto (visão computacional), citada na visão de transformação, fica para a próxima etapa.

Infraestrutura · 1 de 4
MongoDB Atlas

O "banco legado" da empresa

O que é

backend/db.js expõe uma API no estilo MongoDB (find, findOne, insertOne, updateOne, deleteOne, count). Em produção ela usa o driver oficial conectado ao MongoDB Atlas.

Sem MONGODB_URI (desenvolvimento) ou se o Atlas não responder, a mesma API roda sobre um JSON local em data/db.json, e o site avisa que está em modo degradado.

Coleções (seed em data/seed.json)

materiais (12) · residuos (8) · movimentacoes (8) · politicas (4) · auditorias · indicadores · empresa (EcoNova Indústria Ltda.)

O seed só é aplicado em coleções vazias (idempotente): redeployar nunca duplica dados. POST /api/reset restaura o estado original da demo.

Conversas do agente ficam na coleção conversas, ligadas ao perfil que as criou.

function mongoCollection(name) {               // Atlas (driver oficial)

  };
}

function collection(name) {                    // o resto do código só chama isto
  return isMongo() ? mongoCollection(name) : memCollection(name);

Banco vetorial — papel do Qdrant

Indexar → buscar por similaridade

O que faz

Mesmo papel do Qdrant no diagrama do checkpoint: guardar vetores dos materiais e resíduos e permitir busca semântica. Implementado em backend/vectorstore.js com embeddings TF-IDF + similaridade de cosseno e stemming (ex.: plásticos → plastico casa com a categoria Plástico).

32 documentos: 12 materiais + 8 resíduos + 8 movimentações + 4 políticas → vocabulário de ~240 termos indexado em memória.

Infraestrutura · 3 de 4
Ollama Cloud — agente de IA

LLM na nuvem que responde as perguntas

Conexão

API ollama.com/api/chat com Authorization: Bearer e o modelo gemma4:31b-cloud (configurável via OLLAMA_URL / OLLAMA_MODEL; o mesmo código fala com um Ollama local). Usado só em RF01 e RF03.

Resiliência

Se a chamada falhar ou estourar o tempo, fallback() responde com regras locais e a UI mostra "Ollama offline". O site nunca quebra.

Status visível

GET /api/health (app.js:107) expõe disponibilidade e modelos — vira a pílula verde/vermelha no topo do site.

backend/ollama.js:53 — chat com degradação elegante

async function chat(messages, opts = {}) {
  try {
    const res = await fetch(`${OLLAMA_URL}/api/chat`, {
      method: 'POST', headers: authHeaders(),          // Bearer na cloud
      body: JSON.stringify({ model: OLLAMA_MODEL, messages, stream: false }),
      signal: ctrl.signal,                             // timeout de 45 s
    });
    return { text: data.message.content, source: 'ollama', model: body.model };
  } catch (e) {                                        // Ollama fora do ar?
    return { text: fallback(messages), source: 'fallback', model: 'rule-based' };
  }
}

Por que cloud: o site roda na Vercel (serverless), que não tem GPU nem um Ollama local. A chave OLLAMA_API_KEY fica nas variáveis de ambiente, fora do código.

Como funciona — backend/auth.js

  • POST /api/auth/login devolve um token assinado (HMAC), válido por 12 h, sem estado — funciona em serverless
  • Toda rota exige o token; sem ele a API responde 401
  • Rotas de escrita checam a permissão do perfil; sem ela, 403 — mesmo chamando a API direto
  • Cada conversa do agente pertence a quem a criou
  • A auditoria grava nome, e-mail, setor e perfil de quem agiu

function requirePermission(permission) {

Roteiro da demo (5 passos)

  1. Login como Auditor → somente leitura, sem botões de cadastro; sair e entrar como Gestor
  2. Dashboard → KPIs do Mongo (RF05) → botão "Analisar com IA" (RF01)
  3. Estoque → CRUD (RF04) → "Reindexar RAG" (RF02)
  4. Agente IA → "Qual o saldo de plásticos?" com fontes e ms (RF03 + RNF02)
  5. Auditoria → tudo que foi feito fica registrado com o perfil de quem fez (RF06)
